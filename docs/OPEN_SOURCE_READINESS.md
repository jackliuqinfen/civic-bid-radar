# 开源准备审查

## 发布判断

现版本适合作为私有演示候选。公开版本以「自托管采购公告雷达」为边界。第一版体验聚焦公告列表、项目及标段关联、原文证据、公司初筛和站内提醒。财务和外部采集涉及额外的权限及依赖，作为管理员按需开启的能力单独验收。

### 已完成

- 用文件白名单从工作区建立独立仓库。历史部署配置、品牌图像、实际财务人员规则、旧系统同步器和不完整的上游工程均从候选范围移除。
- 移除内置生产存储目标。对象存储需要显式配置桶、地域和凭据，采集与索引脚本需要显式指定数据库路径。AI 默认关闭，演示以虚构数据启动。
- 加入本地初始化、复现命令、冒烟脚本、可重装的 npm 锁文件、第三方清单和安全报告入口说明。演示账号密码按安装随机生成，只写到权限 0600 的本地凭据文件。
- 原始代码、提交记录和业务数据保留在原位置。审查使用工作区、候选目录和本机隔离运行环境。

### 公开前阻断项

| 优先级 | 事项 | 通过条件 |
| --- | --- | --- |
| P0 | 权利与项目许可 | 确认代码著作权归属、共同贡献与外部代码来源，明确公司制度和品牌素材的可公开范围。建议审议 Apache-2.0，或在偏好简洁时用 MIT，由权利人批准并加入相应 LICENSE。 |
| P0 | 身份、权限与外联边界 | 对提醒、资料、附件下载与财务做角色 × 公司 × 功能的允许和拒绝用例。尤其核对资料到期提醒的公司可见与写入范围。对公网部署检查反代覆盖客户端地址、HTTPS、出站目的地与文件上传隔离。 |
| P0 | 资格准确性 | 恢复原文缺失、附件未读、联合体、有效期和只凭标签时的保守行为。以原文和证照做回归门槛，条款在后台补齐后更新匹配。 |
| P0 | 数据与秘密 | 确认新仓库所有提交、分支、标签、发布附件和演示镜像均通过秘密扫描，任何业务数据、证照、人员档案、账户、日志和生产连接信息均需移除。已有聊天、脚本或资料中的真实凭据由运维确认轮换。 |
| P1 | 可重复部署 | 扩展到 Linux 新机与容器验收。给可选 Python 和 OCR 依赖加版本清单、资源和许可。拆出私有部署配置，验证备份恢复、数据迁移、权限和外联停用。 |
| P1 | 开放治理 | 配置 CI 门禁、版本发布规则、更新与回滚说明、维护联系人、议题模板、安全报告渠道和数据来源接入准则。 |

### 候选架构和公开边界

- 当前工作区以单个 Node 入口和浏览器资产为主，仓库未包含完整旧上游爬虫的支持模块。首发可运行自托管应用与通用采集适配，独立上游连接作为后续插件能力。前端发布目录中的文本 JavaScript 已作为实际可编辑实现随候选保留。
- 依赖锁文件和 npm 审计只覆盖 npm 安装树。Python、OCR、字体和容器镜像为独立的许可与安全审计对象。
- 原系统的基线有资格与自动公司推断方面的失败；测试保留原断言以便验收，并优先将无证据的推荐路径当作公开阻断。
- 私有候选用于验证能否复用。发布到公网前须完成上表检查，并决定公开哪些模块和样例。
